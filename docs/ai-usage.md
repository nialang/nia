# AI Usage

AI-assisted work is welcome in the Nia project.

AI is a tool. It can be used like an editor, search engine, script generator,
compiler diagnostic, pair programmer, contractor, or any other aid. The use of a
tool does not change who is responsible for the work.

Tools do not own code. People do.

## Responsibility

Anyone submitting AI-assisted work is responsible for the result. Do not submit
code, tests, or documentation that you cannot understand, explain, review, and
maintain.

AI-assisted code must be reviewed by a human before submission. For code, this
means line-by-line review, not a quick skim of the final diff.

The submitter is also responsible for provenance and licensing. AI must not be
used to launder copyrighted code, incompatible license material, private source,
or text copied from elsewhere without permission.

## Disclosure

Routine AI assistance does not need a special label. The project cares about the
quality, clarity, provenance, and maintainability of the submitted work.

When a substantial part of a change was produced with AI assistance, mention it
briefly in the pull request or discussion. This is not a stigma; it helps
reviewers focus on the areas that need careful validation.

## Review Expectations

AI-assisted work is held to the same standard as any other contribution:

- it must fit the current language design;
- it must follow the compiler architecture;
- it must include appropriate tests;
- it must pass formatting, linting, and test checks;
- it must not introduce code the author cannot justify.

Reviewers may ask the submitter to explain any part of the change. If the
submitter cannot explain it, the change is not ready.

## Maintainer Use

The maintainer may also use AI tools while developing Nia. The same rule applies:
human responsibility remains with the person submitting and merging the work.
